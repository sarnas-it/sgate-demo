# Процесс статического анализа по ГОСТ Р 71207-2024

Документ закрывает организационную часть стандарта: разделы 5, 9 и SLA
разметки. SGATE поставляет инструменты контроля, заказчик — исполнение
процесса.

## Роли (раздел 9)

| Роль | Что делает | Минимальные компетенции (9.2, 9.3) |
|---|---|---|
| Владелец процесса SAST | настраивает анализатор, ведёт baseline, отчитывается | архитектура ПО, жизненный цикл, выбор анализаторов |
| Разметчик | относит предупреждения к категориям 5.5 | язык проекта, анализ потока данных, оценка влияния на безопасность |
| Владелец кода | исправляет истинные предупреждения | язык, архитектура своего модуля |
| Независимый контролёр | ежемесячный контроль устранения (5.11) | не участвовал в анализе и разметке этого ПО |

Матрица компетенций ведётся заказчиком; шаблон — в приложении к договору.
SGATE проводит обучение разметке и выдаёт чек-лист.

## Первичная настройка (5.4)

1. Определить языки и точки сборки: для Go — наличие `go.mod`, для C/C++ —
   `compile_commands.json`.
2. Выбрать анализаторы в `analyzers.yaml`: только те, что покрывают типы 6.3
   для языков проекта.
3. Запустить первичный анализ и **сохранить** его: `sgate -record .sgate/runs`.
4. Разметить все предупреждения: `sgate mark -run <id> -n <номер> -category …`.
   Это начальная база предупреждений (5.4).
5. Зафиксировать baseline для гейта: `sgate -write-baseline .sgate/baseline.json`.

## Регулярный цикл (5.6)

| Событие | Что запускается | Предельный срок просмотра |
|---|---|---|
| Каждый PR / коммит | `sgate` по изменённым частям, `compare` с предыдущим запуском | 3 рабочих дня (5.8 а) |
| Полный анализ | `sgate` по всему коду + `-record` | не реже 1 раза в 10 рабочих дней (5.6), просмотр 10 рабочих дней (5.8 б) |
| Релиз | полный анализ + отчёт о разметке | блокирующие high — до релиза (5.9) |

Результаты каждого запуска хранятся в `.sgate/runs/<id>/` — это и есть
хранилище результатов (5.6, 8.8). Удалять старые запуски можно только после
закрытия отчётного периода.

## Пересмотр конфигурации (5.12)

Конфигурация пересматривается при смене архитектуры, добавлении зависимостей,
обновлении анализатора и **при изменении флагов, влияющих на результат**
(например, `-concurrency` у gosec). Дайджесты образов фиксированы: тег без
дайджеста — это другая версия анализатора при следующем запуске, и тогда
сравнение запусков (8.9) теряет смысл.

## Разметка (5.5, 8.6)

Три категории, расширять перечень не требуется:

| Категория | Когда | Что дальше |
|---|---|---|
| `true` | ошибка реальна | исправить или запланировать в 10 рабочих дней (5.9) |
| `false` | анализатор ошибся | скрывается при сравнении запусков (8.9), не блокирует |
| `accepted` | ошибка реальна, но исправление не требуется | нужны `-owner` и `-expires`, иначе команда `mark` откажет |

```bash
# посмотреть запуск и выбрать предупреждение по номеру
sgate runs -dir .sgate/runs
sgate compare -cur .sgate/runs/<id> -prev -1

# разметить
sgate mark -run .sgate/runs/<id> -n 12 -category false -comment "значение из конфигурации"
sgate mark -run .sgate/runs/<id> -n 15 -category accepted \
  -owner "backend-team" -expires 2027-03-31 -comment "совместимость с внешним API"
```

Правило: `accepted` без владельца и срока — не решение, а отложенная
проблема. Поэтому команда их требует.

## Контроль (5.9–5.11)

- **5.9.** Истинное предупреждение живёт в трекере со ссылкой на
  `file:line` и fingerprint; исправление закрывает его в том же цикле.
- **5.10.** Устранённые истинные ошибки передаются в DAST-контур как
  подсказка для проверки (SGATE DAST поддерживает список целей).
- **5.11.** Раз в месяц независимый контролёр сверяет: сколько истинных
  разметок закрыто, сколько просрочено, сколько `accepted` истекло.
  Инструменты: `sgate runs`, `sgate compare`, `meta.json` с числом разметок.

## Пример месячного отчёта

```
Запусков за период:            4
Предупреждений (последний):    418
Разметка: true 12, false 149, accepted 7
Просрочено accepted:           1  (owner: api-team, срок 2026-11-15)
Новых high без разметки:       0
Средний срок просмотра:        1,8 рабочих дня (SLA 3)
```

## Ответственность

SGATE отвечает за: корректность анализаторов, полноту типов 6.3, показатели
8.4 на квалификационном наборе, сохранность запусков и разметки.
Заказчик отвечает за: соблюдение сроков просмотра, исправление истинных
предупреждений, компетенции специалистов (9.2, 9.3) и независимый контроль.
