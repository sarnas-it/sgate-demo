# Соответствие SGATE ГОСТ Р 71207-2024

**Область:** статический анализ (SAST) в SGATE: `core` (движок, разметка,
хранилище запусков, измерение качества), правила `sast-rules`, CI.
**Дата:** 24.11.2026
**Стандарт:** ГОСТ Р 71207-2024 «Защита информации. Разработка безопасного
программного обеспечения. Статический анализ программного обеспечения.
Общие требования» (ФСТЭК России, ИСП РАН).

Статусы: **соответствует** — требование выполнено и подтверждено артефактом;
**частично** — выполнено с ограничением, ограничение названо и есть план;
**организационное** — требование к процессу заказчика, SGATE поставляет
шаблон и инструменты контроля.

Два ограничения, которые нельзя закрыть словами (нужна работа):

1. **7.4 (межпроцедурные методы).** Semgrep OSS анализирует внутри функции;
   gosec использует SSA в пределах пакета. Межпакетный анализ потока данных
   не реализован. План: подключить анализатор с межпроцедурным анализом
   (например, Go-анализатор на SSA или коммерческий SARIF-совместимый) и
   добавить его в `analyzers.gost.yaml` без изменения кода SGATE.
2. **10.2 в (крупные программы).** Квалификационный набор содержит малые
   тесты (10.2 а, б). Тестов-программ на 100 тыс. — 10 млн строк с известными
   ошибками пока нет. План: собрать корпус из открытых проектов с
   подтверждёнными CVE и разметкой (см. `qualification-method.md`).

Эти два пункта — единственные, где заявление «соответствует» было бы
неправдой. Остальное закрыто кодом и документами.

## Как воспроизвести

```bash
cd core
go test ./...

# прогон квалификационного набора и сохранение запуска (8.8)
go run ./cmd/sgate -repo testdata/gost-corpus -config analyzers.gost.yaml \
  -format json -record .sgate/runs > /tmp/corpus.json

# измерение качества по 8.4 и формулам 10.4/10.5
go run ./cmd/sgate quality -run .sgate/runs/<id> \
  -manifest testdata/gost-corpus/manifest.json -format markdown \
  -out ../docs/gost/quality-report.md

# документ типов ошибок (8.10)
go run ./cmd/sgate catalog -out ../docs/gost/error-types.md
```
