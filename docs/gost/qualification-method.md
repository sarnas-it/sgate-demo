# Методика проверки требований к анализатору (раздел 10 ГОСТ Р 71207-2024)

Документ описывает, как SGATE измеряет собственное качество: какой набор
тестов используется, как считается ложное срабатывание и пропуск, что
считается доказательством.

## Что проверяется

| Раздел стандарта | Как проверяется |
|---|---|
| 7.3 (типы ошибок) | матрица покрытия в `error-types.md` + набор тестов по каждому типу 6.3 |
| 7.4–7.6 (методы) | анализ документации и конфигурации; ограничения зафиксированы в `compliance-matrix.md` |
| 8.4 (качество) | измерение на квалификационном наборе, формулы 10.4 и 10.5 |
| 8.5–8.9 (результаты, разметка, хранение, сравнение) | воспроизводимые команды и тесты в `core/internal/*` |
| 8.10 (документация типов) | `error-types.md`, генерируется `sgate catalog` |
| 8.11 (открытый формат) | SARIF 2.1.0 в CI-артефакте |

## Квалификационный набор (10.2)

Каталог: `core/testdata/gost-corpus`.

| Группа | Файлы | Назначение |
|---|---|---|
| 10.2 а) — полнота | `taint/*.go`, `overflow/*.go`, `bounds/*.go`, `crypto/*.go`, `perms/*.go`, `creds/*.go` | 12 ошибок четырёх типов 6.3; проверяют пропуски |
| 10.2 б) — отсутствие FP | `clean/handlers.go` | параметризованный SQL, SHA-256, права 0600; ни одного предупреждения |

Каждая ошибка помечена в коде маркером:

```go
return db.Query("SELECT id FROM users WHERE name = '" + name + "'") // GOST:6.3а CWE-89
```

`manifest.json` содержит файл, строку, тип 6.3 и CWE (10.3). Тест
`TestCorpusManifestMatchesMarkers` сверяет маркеры с манифестом: набор не
может незаметно разъехаться.

Требования к набору, которые пока не закрыты:

- **10.2 в): крупные программы.** В наборе нет программ на 100 тыс. —
  10 млн строк. Полевой прогон на TaskTracker (1 243 Go-файла) приведён
  отдельно как наблюдение, а не как квалификационное измерение: у него нет
  полной разметки всех предупреждений. План — корпус открытых проектов с
  подтверждёнными CVE.
- **Модельные и поточные варианты (6.6, 6.7).** Покрыты базовые варианты:
  прямой вызов, передача через параметр, условие. Полная матрица
  (глобальные переменные, вызовы по указателю, сложные структуры) — в
  развитии.

## Формулы (10.4, 10.5)

```
доля ложноположительных  FP = 100 · FPW / TW
доля пропусков           FN = 100 · FN / TB
```

- `FPW` — предупреждения, отнесённые к ложным;
- `TW` — все предупреждения об ошибках;
- `FN` — известные ошибки, которые не найдены;
- `TB` — все известные ошибки набора.

Порог по 8.4: `FP ≤ 50 %` и `FN ≤ 50 %`.

Что считается ложным срабатыванием в нашей реализации:

- предупреждение на «чистом» файле — всегда FP (10.2 б требует нуля);
- предупреждение на файле с ошибкой, не совпавшее ни с одной описанной
  ошибкой, — FP;
- дубль одного дефекта разными правилами (импорт + вызов, G501 + G401) —
  **не** FP: это одно предупреждение об одной ошибке, иначе показатель
  наказывает за архитектуру набора правил, а не за качество анализа.

Предупреждения, у которых тип не относится к 6.3 (стиль, необработанные
ошибки, качество кода), в TW/FPW не входят: 8.4 говорит о критических
типах. Их количество выводится отдельной строкой отчёта.

## Как воспроизвести

```bash
cd core

# 1. прогон набора с сохранением запуска
go run ./cmd/sgate -repo testdata/gost-corpus -config analyzers.gost.yaml \
  -format json -record .sgate/runs > /tmp/corpus.json

# 2. измерение (8.4, 10.4, 10.5); код возврата 1, если порог нарушен
go run ./cmd/sgate quality -run .sgate/runs/<id> \
  -manifest testdata/gost-corpus/manifest.json \
  -format markdown -out ../docs/gost/quality-report.md

# 3. в CI то же делает .github/workflows/sgate-gost.yml и падает при FP/FN > 50 %
```

Отчёт `quality-report.md` содержит: TB, TP, FN, TW, FPW, обе доли,
разбивку по типам 6.3, перечень пропущенных ошибок и ложных срабатываний.

## Текущий результат

| Показатель | Значение | Порог |
|---|---|---|
| Ошибок в наборе (TB) | 12 | — |
| Обнаружено (TP) | 12 | — |
| Пропуски (FN) | 0 % | ≤ 50 % |
| Ложные (FPW/TW) | 5,6 % | ≤ 50 % |

Одно ложное срабатывание: `gosec G115` на `byte(rand.Intn(256))` —
преобразование в `byte` безопасно, но формально попадает под проверку
сужения. Это честный FP, он не скрывается: по типу 6.3б FP = 50 %, ровно на
границе. Если правило начнёт мешать, его место — в разметке `false`, а не в
удалении из набора.

## Воспроизводимость

Измерение обязано повторяться: иначе 10.4 и 10.5 ничего не значат, а
сравнение запусков (8.9) показывает ложные «исчезло/появилось».

Проверка на реальном репозитории (TaskTracker, один и тот же коммит
`e04bb55`, gosec в docker, одинаковый конфиг):

| Прогон | Находок | G705 | G706 |
|---|---:|---:|---:|
| параллельный анализ (по умолчанию) | 416 | 3 | 42 |
| параллельный анализ, повтор | 479 | 5 | 94 |
| `-concurrency=1`, повтор 1 | 479 | 5 | 94 |
| `-concurrency=1`, повтор 2 | 479 | 5 | 94 |

Вывод: при параллельном анализе gosec теряет часть taint-находок. Набор
fingerprint'ов двух прогонов с `-concurrency=1` совпал полностью. Поэтому
`-concurrency=1` зафиксирован в `analyzers.gost.yaml` и в основном
`analyzers.yaml`, а конфигурация анализатора пересматривается по 5.12.
Цена — скорость: 479 находок за 115 с против 179 с при параллельном режиме,
то есть двукратный запас по времени и всё равно далеко до предела 48 ч (8.3).

## Ограничения, которые важно проговорить

0. Набор измеряет **детерминированный** режим (`-concurrency=1`). Любой
   другой режим даёт другой результат и к зачёту по 8.4 не принимается.
1. Набор малый: 12 ошибок. Он проверяет покрытие типов и отсутствие
   грубых FP, но не заменяет корпус на сотни тысяч строк.
2. Измерение зависит от версии анализаторов. Поэтому образы закреплены
   дайджестами, а не тегами.
3. Правила Semgrep для набора — локальные (офлайн). Расширение `p/golang`
   требует сети и в измерении не участвует, чтобы результат был
   воспроизводим на изолированном стенде.
