# ADR 0005: on-prem и offline

## Контекст

Заказчик может запретить внешние SaaS и egress. SGATE должен работать в
контуре: без облачных API, внешних LLM и скачивания баз на каждом прогоне.

## Решение

### SAST

- все образы анализаторов закреплены по `@sha256` (`analyzers.lock`);
- анализаторы запускаются с `--network none`, non-root, read-only repo;
- результаты кэшируются локально по коммиту;
- внешние LLM не используются; Semgrep работает по локальным правилам.

### DAST

- сканируется только scope из `dast/scope.yaml`: стенд или согласованная цель;
- образы ZAP/nuclei/feroxbuster закреплены по digest (`scanners.lock`);
- шаблоны nuclei/словари feroxbuster монтируются из контура;
- никаких SaaS-отчётов: отчёты и SARIF остаются локально.

### Поставка

- бинарники/образы передаются через внутренний registry или файлом;
- обновление — новый digest + прогон тестов, без автообновления;
- проверка: `scripts/check-pins.sh`, `--network none`, отчёт в контуре.

## Ограничения

- нет автоматического обновления баз/правил; нужен регламент;
- для nuclei templates нужен локальный набор, иначе проверки неполные;
- DAST full scan требует тестового стенда и учёток;
- подпись образов (cosign) и SBOM — следующий шаг.

## Следствия

- воспроизводимость важнее свежести «по умолчанию»;
- обновление анализатора — отдельный PR с digest;
- можно пройти требования on-prem без облачных зависимостей.
