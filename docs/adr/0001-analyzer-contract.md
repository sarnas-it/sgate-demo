# ADR 0001: контракт SAST-анализатора

## Контекст

SGATE уже запускает Semgrep для Go и PHP. Чтобы добавлять любой язык, нельзя
писать `if language == "go"` в коде: нужен сменный адаптер.

## Варианты

1. **CLI/OCI + SARIF** — анализатор запускается как контейнер или команда,
   результат — SARIF 2.1.0.
2. **Remote-сервис анализатора** — SGATE вызывает HTTP/gRPC-сервис.
3. **LSP-сервер** — интерактивный протокол редактора.
4. **Встроенные библиотеки** — импорт анализатора в SGATE.

## Решение

Выбран **CLI/OCI + SARIF**:

- Semgrep уже работает как контейнер и отдаёт SARIF;
- большинство SAST-инструментов умеют CLI и SARIF;
- контейнер даёт версионирование, изоляцию и offline;
- remote-сервис нарушает требование «данные не покидают контур»;
- LSP не подходит для CI и пакетной обработки;
- встроенные библиотеки привязывают SGATE к языкам и лицензиям.

## Следствия

- `analyzers.yaml` — единственная точка добавления языка;
- SGATE не исполняет код анализатора в своём процессе;
- контейнеры запускаются с `--network none`, non-root, read-only repo, без
  docker.sock;
- новый адаптер обязан иметь fixture с известными находками и SARIF;
- severity нормализуется по CVSS (`security-severity`) или уровню SARIF.

## Открытые вопросы

- подпись образов (cosign) и SBOM — M2;
- remote-анализаторы для сред без Docker — отдельное решение;
- baseline и fingerprint — M2.
