# ADR 0002: стек DAST для SGATE

## Контекст

Сейчас есть пассивный аудит по OWASP WSTG: заголовки, TLS, версии CMS и
плагинов, открытые служебные файлы. Активных проверок нет. Нужен стек, который
закрывает активную часть WSTG и встраивается в SGATE как ещё один источник
находок.

## Варианты

| Инструмент | Что даёт | Ограничения |
|---|---|---|
| **OWASP ZAP** | baseline и full scan, crawl, auth, JSON/SARIF-отчёты, большой набор правил | тяжёлый, шумный, полноценный full scan требует стенда и времени |
| **nuclei** | шаблоны на CVE, misconfig, exposed panels; быстрый, YAML-шаблоны | не заменяет crawl и бизнес-логику; качество зависит от шаблонов |
| **feroxbuster** | поиск скрытых путей и файлов, словари | только discovery, не проверка уязвимостей |
| **nettacker** | автопентест, управление находками | тяжелее, меньше прозрачности, нужен пилот |
| **gotestwaf** | проверка WAF/ gateway на классы атак | не сканер приложения, а тест защиты |
| **vuls** | CVE ОС и контейнеров | не DAST, другой слой |

## Решение

Базовый стек пилота:

1. **ZAP baseline** — обязательный быстрый прогон по стенду на каждом запуске.
2. **ZAP full** — ночной прогон с аутентификацией и crawl.
3. **nuclei** — шаблонные проверки CVE/misconfig/exposed.
4. **feroxbuster** — discovery скрытых путей, результаты идут в общий отчёт.
5. **nettacker** и **gotestwaf** — оценить на пилоте, не включать в MVP.
6. **vuls** — оставить в слое container/host security, не смешивать с DAST.

Почему ZAP: открытый, поддерживаемый, умеет auth и отчёты, покрывает
значимую часть активного WSTG. nuclei дополняет его шаблонами, feroxbuster —
discovery. Один инструмент не закрывает всё.

## Безопасность

- только тестовый стенд или письменно согласованный scope;
- allowlist целей, rate limit, kill switch;
- запрет прод-кредов, только тестовые учётки;
- отчёты и логи — в контуре;
- активные проверки не запускаются на чужом периметре без согласия.

## Открытые вопросы

- нужен ли ZAP full с аутентификацией в MVP или достаточно baseline;
- формат отчётов: JSON ZAP → общая модель или SARIF;
- как дедуплицировать ZAP/nuclei с SAST/SCA;
- порог блокировки: CRITICAL/HIGH или только подтверждённые находки.

## Следствия

- B1: политика авторизации и безопасности;
- B2: стенд Juice Shop/DVWA;
- B3: discovery и scope;
- B4: адаптеры ZAP/nuclei/feroxbuster.
