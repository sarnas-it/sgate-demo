# Отчёт: что собрано и чем доказано

Дата: 22.11.2026. Проект SGATE, репозиторий
[`sarnas-it/sgate-demo`](https://github.com/sarnas-it/sgate-demo).

## Что собрано

Сервис из двух слоёв, как договорились:

1. **SCA (Deps)** — уязвимые зависимости по подписанному офлайн-пакету OSV.
2. **Секреты и ПДн (Guardrail)** — дифф PR, блокировка при находке.

Оба слоя останавливают пайплайн и работают без выхода в интернет.

## Ограничения и остаточный риск

- Демо-пакет баз содержит 10 записей OSV и подписан одноразовым ключом. Для
  продакшена — `deps sync` и ключ Sarnas.
- В демо-репозитории есть вымышленные секрет и ПДн. Репозиторий приватный,
  значения замаскированы; в продакшене такого быть не должно.
- Guardrail-образ `v0.1.0` не содержит правило `full_name_ru`; ФИО в демо не
  ловится, остальные ПДн — ловятся. Для полноты нужен новый образ с тегом по
  SHA.
- Дашборд `deps.sarnas.ru:8443` отвечает (401 по `--resolve`), но у домена
  сейчас **нет A-записи** в DNS — для показа нужно восстановить запись.
- CI использует self-hosted раннер на `mon`; для GitHub-hosted нужен доступ к
  минутам Actions или сборка образа с бинарниками.
- SAST/DAST в сервис не входят и не проверялись.
- Юридическая оценка 152-ФЗ — на стороне организации.

## Что нужно сделать перед показом

1. Восстановить DNS `deps.sarnas.ru` и проверить дашборд в браузере.
2. Прислать владельцу политики матрицу block/warn и получить ответ по ПДн.
3. Согласовать даты и 1–2 репозитория для пилота.
4. Решить, нужен ли on-prem с первого дня или SaaS на демо.
5. Получить полные требования из карточки SberUnity (SGATE-1).
