# Security Gate для АльфаСтрахования — one-pager

**Кому:** АльфаСтрахование, блок разработки и ИБ.
**Что:** два автоматических гейта в CI/CD, которые останавливают пайплайн:
уязвимые зависимости и утечки секретов/ПДн.
**Срок пилота:** 3 недели, 1–2 репозитория.
**Основа:** Deps (SCA) и Guardrail (секреты/ПДн) уже работают. Оба слоя
работают в контуре заказчика, без выхода кода и метаданных наружу.

## Проблема

Проверки безопасности либо не встроены в пайплайн, либо живут отдельным
отчётом, который никто не читает перед релизом. Критическая уязвимость или
ключ в коде уходят в прод, а ИБ узнаёт об этом из инцидента.

## Решение

```
PR / push ──► Guardrail   секреты и ПДн в диффе
          ──► Deps       уязвимые зависимости по офлайн-базе OSV
                     │
                     ▼
        Политика: CRITICAL/HIGH и любая утечка — стоп
                     │
                     ├──► check run / комментарий в PR
                     ├──► issue «ежедневный отчёт»
                     └──► дашборд и история
```

Что это даёт:

- **остановку пайпа**, а не «отчёт для галочки»;
- **офлайн-режим**: ни код, ни имена пакетов не покидают контур;
- **план исправления**: до какой версии обновить, какие breaking changes;
- **приоритизацию**: достижимые уязвимости и прямые зависимости вперёд;
- **один язык** для разработки и ИБ: check run, PR-комментарий, issue, SARIF;
- **предсказуемую стоимость**: ≈3–6 ₽ за ревью PR, дневной лимит настраивается.

## Что уже работает

- **Deps**: разбор 7 типов lock-файлов, OSV/deps.dev/npm, CVSS и severity,
  достижимость (`govulncheck` для Go), план обновления, GitHub App,
  комментарий в PR, check run, ночной обход, issue, дашборд.
- **Офлайн-пакет баз**: подписанный пакет OSV, проверка свежести и подписи,
  работа без сети.
- **Guardrail**: дифф PR/push, правила секретов и ПДн РФ, SARIF/JSON,
  allowlist, маскирование значений, контейнерное действие для GitHub.
- **Живой пример**: [issue #152](https://github.com/sarnas-it/web-sarnas/issues/152)
  — 11 уязвимостей, 4 новых, 2 CRITICAL RCE в `next 16.3.8`.

## Что входит в пилот

- Установка и настройка Deps (GitHub App или CLI) на 1–2 репозитория.
- Офлайн-пакет баз и регламент его обновления.
- Guardrail в PR как обязательная проверка.
- Политика block/warn/allowlist с владельцем и сроком исключений.
- Ежедневный отчёт и дашборд.
- Runbook и передача команде заказчика.
- Метрики пилота.

## Чего в сервисе нет

- **SAST/DAST не входят в ядро.** Semgrep/Trivy — отдельные слои на будущее,
  в пилоте не заявляются.
- **GitLab/Jenkins** — через CLI; нативные адаптеры — отдельная работа.
- **SSO, SIEM, DLP** — вне пилота.
- **Ложные срабатывания** неизбежны; достижимость и allowlist снижают шум, но
  калибровка идёт на репозиториях заказчика.

## Метрики пилота

| Метрика | Как считаем |
|---|---|
| Уязвимости по severity | снимок Deps на старте и в конце |
| Доля достижимых | отчёт Deps |
| Время до исправления | от первого срабатывания до зелёного PR |
| Заблокированные PR | журнал check run |
| Найдено секретов/ПДн | отчёт Guardrail |
| Ложные срабатывания | разбор с командой заказчика, доля от всех находок |

## Что нужно от Альфы

1. 1–2 репозитория для пилота и языки/экосистемы.
2. Платформа: GitHub, GitLab или Jenkins; self-hosted или облако.
3. Что блокирует релиз: CRITICAL/HIGH, только достижимые или всё.
4. Требования к развёртыванию: on-prem, 152-ФЗ, обновление баз.
5. Владелец политики и срок пилота.

## Демо

Репозиторий [`sgate-demo`](https://github.com/sarnas-it/sgate-demo):
`scripts/demo.sh` прогоняет пять сценариев в контейнере без сети — секрет,
ПДн, CRITICAL-зависимость, исправление и чистый дифф — и проверяет, что гейт
сработал именно так, как должен.
